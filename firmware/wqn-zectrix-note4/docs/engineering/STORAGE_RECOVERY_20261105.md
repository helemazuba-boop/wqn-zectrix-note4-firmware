# R-18 启动存储恢复入口

schema、存储初始化或同步检查点启动检查失败后，设备进入可交互的维护界面。
用户可以导出串口诊断、重启检查、查看数据保全说明；可读取且受当前固件支持的
介质允许经过明确确认后清除本地数据。原启动门禁继续阻止业务、网络、音频和
普通 UI 启动。恢复代码运行在 `app_main`，与 `DeviceUiTask` 不同时消费显示结果。

## 用户操作和数据边界

默认选中“导出诊断到串口”。初次进入异步读取元数据，后续选择该项会重新读取并
输出错误、是否存在版本标记、版本号、reset-id 长度和重置策略。原始启动错误在
启动日志中保留。诊断不含凭据、reset-id 字节、业务记录或完整 Flash 镜像；界面
明确告知串口诊断不是业务数据备份。“保全数据说明”指导在需要未同步数据时先
获取原始镜像；R-08 的无损 outbox 维修仍需另行实现。

清除步骤：

1. 选择“清除本地数据”，显示删除 WiFi、配对、学习包和未同步记录的警告。
2. 警告获得匹配的 `Presented` 结果后，重新按住确认满 2 秒再松开。
   按上键可以在提交前取消；短按、重复长按通知、旧序号、旧时间戳和未呈现警告
   都不能授权。仅 raw Press/Release 的新手势可以提交重置。
3. StorageService 再次读取并核对用户确认的版本标记、reset-id 和待处理 intent。
   状态改变、较新数据版本、读取失败或未知 intent 均拒绝，不覆盖旧 intent。
4. 只记录既有 `reset_pending` 协议，不在恢复 UI 中格式化、清数据或重启。
   保存成功后显示“下次启动将清除本地数据”，需新短按确认才重启。
5. 写入/commit 返回错误时显示“重置请求可能已保存，下次启动可能执行已确认的
   数据清除”。这类结果不能显示为已取消或保证无变化；也不会自动重试重置。

普通“重启并重试”也有单独确认页，提示已有重置请求会在启动时继续执行。
较新 schema、NVS 不可读和不支持的 intent 仍提供诊断/重启/保全说明，禁用清除。
有效的既有待处理 intent 显示提示并允许经确认重启继续，避免生成新的清除请求。
授权重置本身是数据清除流程，不代表无损维修。

## 任务、显示和启动协议

`storage_recovery_service.cpp` 启动维护协调器及既有 StorageService；不调用
`InitStorage()`、初始化业务缓存或启动同步。唯一静态邮箱沿
Idle → Filling → Queued → Running → Done 流转；request/result 在内部静态 RAM，
协调器栈可以使用 PSRAM，但 NVS 操作仅在 StorageService 的内部栈事务上运行。
发布结果后仍保持 busy，单一 UI 消费者按 operation-id ACK 后才允许下一请求。
任务通知只用于唤醒，失败重试不复用调用方栈上的 payload。

恢复 UI 不同步访问 NVS/SPIFFS，也不直接调用 EPD 硬件。只保留一个未完成显示
revision，receive 后 ACK；旧视图的成功结果不授权当前视图，无超时猜测释放。
显示失败复用 R-10 的退避、自动尝试上限和新物理按键探测。存在未完成显示时
50 ms 检查结果队列；静止或暂停时等待通知，退避期间按下一期限唤醒。
大 UiFrame 放入恢复专用静态对象，不占 IDF main 栈；构建门禁要求实际编译的
`RunStorageRecoveryUi` 入口帧存在且不超过 1024 B。

实际清除继续由下一次 `EnsureStorageSchema()` 执行原 reset-intent 流程：未来版本
先拒绝；无授权的新介质仍须 `VerifyEmptyMedia`；清除后验证挂载、提交标记，最后
移除 intent。未修改既有 intent 编码、SPIFFS 文件格式和正常设置页重置协议。

## 验证和剩余验收

- `test_storage_schema.py` 编译真实 schema 实现：260 个主机场景、13,814 项检查，
  覆盖 staged/write-through 两种 NVS 可见性、原自动初始化/重置故障与新授权入口。
  检查只读无写入、旧/缺失标记、未来版本拒绝、坏 intent、过期确认、幂等续作、
  写入前后错误及重启。写入失败不会被当作持久化结果确定。
- `test_storage_recovery.py` 编译真实 model、协调器和 UI 循环。model 检查新长按、
  显示确认、忙状态、operation-id、过期事件和不确定结果；协调器检查启动失败
  可重试、静态 payload、错误交付及 ACK；UI 检查串口诊断选择、实际页面文字、
  清除警告失败与旧按键、单 revision、receive-before-ACK、退避/暂停/探测和重启。
  StorageService、NVS、显示、按键和调度使用显式主机端口，不是 RTOS/HIL。
- 三个语义负例删除 2 秒门槛、未呈现保护、写入不确定性提示；必须完成检查并
  以行为断言失败结束，不能把编译、sanitizer 或脚本异常当作成功检出。
- 完整门禁扩为 60 项：29 个运行时入口、10 个 UI 检查、21 个语义负例。
  本批分别验证开发菜单和产品 SDK 配置；产物身份按基线提交加本批 patch 记录。

真实按键/EPD 呈现、main/协调器/StorageService 动态栈水位、物理 NVS/SPIFFS
断电恢复、看门狗、RTC/电源和发布接受仍需最后设备验收。正在执行的 NVS 调用
没有硬完成期限；界面保持 busy，不在未知执行状态下另起清除或宣称已取消。
R-08 会话对账/无损维修与 R-09 原始坏行保全不由本批关闭。
