# R-11：先校正时间，再允许学习

产品决策：新学习操作必须先有校正过的时间。
SNTP 成功回调后的时间可用；从带校时来源且连续性已验证的 RTC 恢复后，仍可离线学习。
未知来源、编译时间、由编译时间派生的 RTC 均不允许学习；历年看似合理不能替代校时。
沿用 WallClockSource / epoch / rtc_continuity，不新增另一套时间来源枚举。

单词、笔记、错题页面的上下选择、打开、揭晓与作答，在进入 reducer 前检查校时状态，
未就绪时只显示“请先联网校正时间”。导航、返回/暂停、设置与计时器仍可操作。
校时成功后，下一次明确操作清除过期的校时提示，继续原有流程。
网络连接后沿用现有 SNTP 机制；可从设置手动同步来请求联网，UI 不等待 NTP 或直接调用存储。

自动单词续段与笔记会话队列同样检查时间，避免通过后台入口开始新学习。
三条新记录路径只接受校时来源的当前 UTC 时间，采样/格式化时 epoch 改变即等待重试。
删除固定 2024 年时间戳回退。未校时时不消费观察 effect、不取得新的 worker 槽位/缓冲 lease。
单词缓冲区已有、先前接受的记录仍按原 ID/时间保存；三域已经分配过 ID/时间的 pending 事实可按原身份重试，
不要求重新校时或分配新身份。已提交或在途任务继续完成。
历史 outbox 内容不重打时间、不补造来源、不清除，上传与本地持久化不以当前校时状态为新门槛。

界面日期显示“时间未校正”，状态栏时间显示 --:--；设置和时间工具保持可用。
有效时间范围为 2024-01-01 至 PCF8563 支持的 2099 年末。
SNTP 表示观测到了校正事件，不构成经过认证的网络时间证明。

主机专项使用实际 wall_clock.cpp、输入分发前的 admission 段、UTC 格式化、三个记录 pump、
笔记会话队列与实际提示方法。下游 reducer、worker、lease 为计数端口，不冒称完整 UI/RTOS/HIL。
428 项覆盖来源、RTC 连续性、上下界、校正前后输入、epoch 漂移、旧缓冲保留与恢复。
另以真实单词 session-start pump 验证未校时时不消费自动续段；RTC 与计时器既有回归一并运行。
8 个负对照须完成断言并按目标语义失败；编译、超时或 sanitizer 异常不能计作通过。

实机待验：冷启动无网、NTP 不可达、成功校时、校时后离线学习、可信/不可信 RTC 深睡恢复，
以及校时切换期间的输入/保存、真实状态栏呈现。旧 val-20261108.2 不包含本批策略。
