# EPD 空闲维护调度修复

状态：实现与主机验证完成，用户已批准本批本地提交；实机 HIL 待执行，未刷机、未推送。
基线：`58de342`。已有的全帧窗口修复 `dad8ec2` 保持不变。

## 问题与范围

原实现由 UI 循环调用 `RequestEpdIdleMaintenance()`，仅在已到期时通知
EPD owner。UI 进入 retained standby 后可能等待至下一分钟；时钟提交又
更新 EPD 活动时间，因而维护期限可能长期错过。EPD owner 自身无限等待
通知，无法独立兑现断电和清理期限。

本批修复维护调度，继续使用现有断电、清理、波形、BUSY 超时、睡眠准备
协议和显示 ACK 路径。应用栏仍使用 partial；`dad8ec2` 的全屏目标窗口及
PMODE 设置未改。它们是否解决电池待机后的实际呈现问题，仍须实机确认。

## 实现

- 显示服务提供仅限 owner 调用的 `EpdIdleMaintenanceDelayMs()`，根据单调
  活动时间、实际 rail 状态、已断电标记和清理欠账计算最近期限。返回 -1
  表示无工作，0 表示已到期。当前配置是 5000ms 断电、45000ms 欠账清理。
- owner 使用可被通知提前唤醒的有期限等待。每次活动、帧或维护后重新计算；
  无工作时仍无限等待。UI 的分钟等待策略不变，没有新任务或定时器。
- 空闲等待不持有显示 SleepLease。执行硬件维护时才申请短期 lease，关闭的
  电源门控会拒绝维护；执行前复核活动代数、待绘制帧和 secondary 槽。
- 待绘制帧优先；空闲命令点的睡眠准备优先于维护。睡眠准备成功后，自动
  维护暂停到下一次被接受的帧，避免睡眠准备成功后重新启动欠账清理；准备失败仍保留有界重试。
- 锁争用、lease 拒绝或仍有欠账时，以绝对重试期限限制到最多每 500ms 一次；
  新活动重新计算期限。任务等待向上取整至 tick，避免零 tick 空转。
- 保留 cleanup=0 随断电期限执行的兼容行为，以及断电关闭而独立清理开启的
  配置。已经断电且无欠账时不安排额外唤醒。
- 删除 UI 轮询触发与跨任务请求标记。存储恢复页交由仍存活的 owner 自动
  维护，正常 UI 未启动也不会失去期限。

## 自动验证

`python3 scripts/test_epd_idle_scheduler.py` 提取生产的期限计算、活动记录、
清理/断电判定、睡眠准备结果发布及 owner 等待循环，以虚拟时间和硬件端口替身运行：

- 100Hz 和 1000Hz 各 677 项检查，均开启 ASan/UBSan；
- UI 60 秒没有任何通知时，仍在 5 秒断电、有欠账时在 45 秒清理；
- 空闲结束、新活动、到点的新帧、延迟提交和 tick 回绕；
- secondary/在途帧、活动代数变化、电源门控拒绝；
- 睡眠准备与维护同到期、准备失败、无关通知、下一帧恢复；
- 硬件端口/操作锁失败、500ms 重试、重试期间的新活动；
- 两种维护分别禁用、cleanup=0 兼容、无欠账和已断电场景；
- 所有等待时维护 lease 与临时 TWDT 订阅均已释放。

脚本可选 `--baseline-refresh <旧版 ui_refresh.cpp>`。用基线生产等待循环
在相同端口下回放，会一直等到第 60 秒的新帧通知，错过两项维护；新循环
能在同样没有 UI 轮询的情况下处理到期工作。这验证软件调度，不能证明
实际 BUSY 时序、光学呈现或多核竞争窗口。

1488 项、栈检查脚本 17 项通过。ESP-IDF 5.5.6 默认配置构建零警告，
M8 与编译 UI 栈门禁通过；CRLF-aware diff 检查通过。
